# Sherwood Contracts

Smart contracts for [Sherwood](https://sherwood.cash) — a privacy mixer and shielded DEX
on the Robinhood chain. Deposits, withdrawals and swaps are shielded with zero-knowledge
proofs, and every asset lives in its own Poseidon Merkle tree inside a single vault.

## Setup

```bash
yarn install
yarn compile
```

## Environment

Copy `.env.example` to `.env` and fill in the values:

```bash
cp .env.example .env
```

The deploy reads the target RPC, the WETH/USDG token addresses, the Uniswap routers to
allowlist and the protocol fee settings. See `.env.example` for the full list.

## Tests

```bash
yarn test
```

## Deploy

Always compile before deploying:

```bash
yarn compile
npx hardhat run scripts/deployRobinhood.js --network robinhood
```

The script deploys the verifier, the on-chain Poseidon hasher, the vault and the swap
logic, allowlists the configured routers and writes the resulting addresses to
`deployments/<network>.json`.

## Architecture

- **SherwoodVault** — the immutable vault. Handles shielded deposits, withdrawals and
  swaps with Groth16 proof verification, holds one Poseidon Merkle tree per asset, and
  collects the protocol fee (always in a quote asset).
- **SwapLogic** — UUPS-upgradeable router logic that builds swap routes across Uniswap
  v2 / v3 / v4. The vault only ever `staticcall`s it to build a route, then executes the
  swap itself against an allowlisted router.
- **MultiAssetMerkleTree** / **MerkleTreeWithHistory** — Poseidon-based Merkle trees with
  a circular root-history buffer.
- **Verifier2** — Groth16 ZK proof verifier (generated by snarkjs).
- **Hasher** — on-chain Poseidon. The bytecode is generated by `circomlibjs` in
  `scripts/compileHasher.js`; there is no Solidity source for this blob, so standard
  explorer Solidity verification does not apply.
- **WZEC** — Sherwood Wrapped Zcash. A plain 18-decimal ERC-20 behind a UUPS proxy: one
  wZEC is one share of the bridge keeper's ZEC-PERP long on Lighter. The keeper (the
  `minter`) mints exactly the filled size on a deposit and holders burn on redemption; the
  `owner` can rotate the minter, upgrade the token, or renounce upgradeability for good. No
  pause, blocklist, fee-on-transfer or rebasing — the vault holds it like any other asset.
  Deploy with `scripts/deployWzec.js`, upgrade with `scripts/upgradeWzec.js`.
- **Proxy** — ERC-1967 UUPS proxy; upgrade authority is controlled by the `admin`.
